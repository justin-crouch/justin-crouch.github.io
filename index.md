## Software Design and Engineering
[This enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact) showcases my skills in UI/UX design, code organization, and the ability to utilize industry standard tools, such as Git for version control and Vue.js for front-end development.

At a consumer level, [the artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip) was improved in its UI and UX. Before, [the artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip) had a clunky and confusing UI that was only viewable on mobile Android devices. Now, the UI has a mobile-first design that supports tablet- and desktop-sized screens, whose elements can be interacted with using the keyboard for accessibility.

At a developer level, [the artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip) was improved in its code structure. Before, the code was vaguely separated into a UI and data layer with non-descriptive variable naming. Now, [the project](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact) follows the MVVM pattern, which uses Vue.js as the View-Model for more efficient development, Vue.js’ concept of Single-File Components for the View ([Single-File Components](https://vuejs.org/guide/scaling-up/sfc.html), 2026), and Pinia for the Model ([Pinia](https://pinia.vuejs.org/), 2026).

The planned course outcome for [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact), Course Outcome #4, has been met. Utilizing a widely used front-end framework to implement a modern UI/UX design, while organizing the code using the MVVM pattern, demonstrates the ability to use well-founded techniques and tools that bring value to users.

Learning these techniques and tools was challenging yet rewarding. Using Vue.js as the front-end framework was the most challenging as the technology was novel to me. However, while using it, I found it easier to implement UI and UX features faster than writing pure HTML, CSS, and JavaScript. 

## Algorithms and Data Structures
[This enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/modules) showcases my skills in analyzing and utilizing appropriate data structures and algorithms to provide value to users. The nature of [this artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip) is to efficiently allow the management of items in an inventory.

However, in the [original artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip), an inventory with hundreds of items can be problematic to navigate for a user since there is a lack of organization when viewing a list of these items and no search feature to ease this burden. [The enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/modules) solves this issue by presenting items in a user’s inventory alphabetically and allows the user to search for items that begin with a specific prefix.

To support the search feature, a [Prefix Tree](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/modules/prefixTree.js) was chosen over other data structures such as a Suffix Array for its ability to add, remove, and look up items in linear time ([Trie Data Structure](https://www.geeksforgeeks.org/dsa/trie-insert-and-search/), 2026). [The enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/modules) also allows the user to filter for items with specific categories and stock levels, thus providing more potential value to the user.

The planned course outcome for [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/modules), Course Outcome #3, has been met. Multiple data structures were analyzed in their capability to search for a dynamic list of words with the smallest runtime footprint. Although Prefix Trees are identified to potentially require significant memory storage, it can be vastly reduced by collapsing certain sequences of nodes ([Sudonull Editorial Team](https://sudonull.com/art-prefix-trees-memory-and-cache-optimization), 2026). However, this optimization is not necessary until actual user feedback indicates memory consumption as an issue.

The test-driven development technique was used to develop [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/modules). Specifically, I learned how to design appropriate [unit tests](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/__tests__) with the Vitest tool to guide the implementation of the Prefix Tree. The greatest challenge was integrating the Prefix Tree into the actual application, mainly due to how Vue.js binds the Model and View layers during runtime. However, using integration tests could have lowered the challenge.

## Database
The [final enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/store/inventory) of this artifact showcases my skills in database design and data management. The [original artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip) used SQLite as its database management system and defined data models so to seamlessly interact between the database and business logic. However, the original codebase was never systematically tested, meaning that its current logic could break in edge-cases or with future features.

With [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/store/inventory), the data models and business logic have associated [unit tests](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/__tests__), which reduces the likelihood of flaws currently existing or being produced in the future. Since the [original artifact](https://github.com/justin-crouch/justin-crouch.github.io/blob/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Android-Artifact.zip) has been translated from an Android application to a web-based application, [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/store/inventory) utilizes a NoSQL object database management system present in all major browsers, namely IndexedDB.

The planned course outcomes, Outcome #4 and Outcome #5, were met with [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/store/inventory). The former is satisfied with the use of IndexedDB as the database management system. This is due to the enhancement requiring a tool that allows for efficient storage and retrieval of numerous items in an inventory within a web browser. 

The latter is satisfied by the properties of an IndexedDB database. Data stored using this management system can only be accessed by the browser on the client’s device that originally saved this data, thereby reducing wireless attack vectors by requiring attackers to have physical access to the client’s device. Additionally, only Javascript code from the original site that the data belongs to can access this data, which prevents other sites from embedding the original site to access this data ([IndexedDB API](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), 2026).

Similar to the previous enhancement, Test-Driven Development using Vitest was utilized to produce [this enhancement](https://github.com/justin-crouch/justin-crouch.github.io/tree/1a26dfce1a5e57172e0809d1d7dea4d3c3aa9100/Web-Artifact/src/store/inventory). Surprisingly, because this technique involves isolating code execution from an actual browser by default, the IndexedDB API was not available as it requires access to a browser’s Window interface.

Two solutions were attempted to solve this issue. The first solution was to run these unit tests within an actual browser using Vitest’s browser mode. However, setting up this mode in Vitest created more issues which could not be solved in the limited time frame.

The second, and chosen, solution was to emulate the IndexedDB API so it could be used independently of any browser during testing. This was made possible by installing the [fake-indexeddb package](https://www.npmjs.com/package/fake-indexeddb), which is a Javascript implementation of IndexedDB that saves data in-memory instead of on-disk.

Using face-indexeddb for testing began by first installing the package with NPM. 
``` 
npm install --save-dev fake-indexeddb
```

Once installed, the package was imported in the test file, which loaded the in-memory IndexedDB API into the global space for the database helper class to use.
```js
// Database.spec.js

// Import vitest testing classes
import { beforeAll, it, ... } from 'vitest';

// Import fake-indexeddb into the global scope
import 'fake-indexeddb/auto';

// Initialize database helper class before any test is ran
// Helper uses global IndexedDB API populated by fake-indexeddb
let dbHelper;
beforeAll(() => {
  dbHelper = new DBHelper();
});

// Begin testing database features
it(...);
```
